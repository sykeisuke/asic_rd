## 2. 概念——物理屋のための最短説明

### 2.1 レイアウトとは何か
チップは**層(レイヤ)ごとの多角形の集合**として製造装置に渡される。ファイル形式が **GDS**。
各レイヤはマスク 1 枚に対応する: 例えば `COMP`(活性領域 = トランジスタの拡散)、
`Poly2`(ゲート)、`Contact`(拡散/ポリ → 第 1 金属)、`Metal1`〜`Metal5`(配線 5 層)、
`Via1`〜`Via4`(金属間の縦接続)。GF180MCU では番号で識別する(`Metal1 = 34/0` など)。

### 2.2 PDK(Process Design Kit)
ファウンドリが配る「このプロセスで設計するための一式」: トランジスタの SPICE モデル
(BSIM4)、レイヤ定義、**設計ルール**(DRC デッキ)、抽出定義(LVS/PEX 用)、
標準セル・I/O セルのライブラリ。我々は GF180MCU のオープン PDK を **コミット
`f6eeac7`** で凍結して使っている(バージョンが動くと検証結果の意味が変わるため)。

### 2.3 DRC(Design Rule Check)
「この形は製造できるか」の機械的検査。ルールは物理に根ざしている:
- **最小幅**(例 `M1.1`: Metal1 ≥ 0.23 µm)— 細すぎる線はリソグラフィで切れる
- **最小間隔**(`M1.2a`: 0.23 µm)— 近すぎるとブリッジする
- **最小面積**(`M1.3`: 0.1444 µm²)— 小さすぎる孤立パターンは剥がれる/解像しない
- **囲み**(`CO.6`: コンタクトを金属が 0.06 µm 囲む)— 合わせずれの余裕
- **密度**(`M1.4` など: 金属密度 ≥ 下限)— CMP(研磨)の均一性。**ダイ全体**で評価するので、
  小さなセル単体では必ず「違反」になる(§5 で詳述)
- ラッチアップ防止(`DF.13/14`: 20 µm 以内にウェル/基板タップ)

DRC は KLayout で、凍結 PDK の公式ルールデッキ(`gf180mcu.drc`)を使う。
wafer.space の受入検査(precheck)も同じデッキなので、ここで通れば提出も通る。

### 2.4 LVS(Layout Versus Schematic)
「描いた図形が、シミュレーションした回路と同じネットワークか」。
1. **抽出**(Magic): 図形の重なりからトランジスタ・容量・配線ネットを認識し、
   SPICE ネットリストを生成する
2. **比較**(Netgen): 回路図側のネットリストと、デバイスの種類・寸法・接続を照合する

「Circuits match uniquely」が合格。デバイスが 1 個でも余分・不足・誤接続なら不一致。
**DRC を通っても LVS で落ちる**のは普通(今回も 2 回ショートを見つけた)。

### 2.5 PEX(Parasitic Extraction)と抽出後シミュレーション
配線には意図しない **寄生容量・抵抗**が乗る。Magic で寄生 R/C 付きのネットリストを
抽出し、同じテストベンチを流して前段(回路図)の数値と比べる。
「レイアウトが性能に効いたか」を初めて定量化できる段階。

### 2.6 トランジェントノイズ
通常の SPICE 過渡解析は決定論的(雑音なし)。**VACASK** は各トランジスタの熱雑音・
ショット雑音・1/f 雑音を時間領域で注入できる(オープンソースでは初)。
サンプル&ホールドで有名な **kT/C 雑音**(1 pF・300 K で 64 µV rms)を
直接「見る」ことができる(§7)。

### 2.7 よく出る構造
- **フィンガー(nf)**: 幅 W のトランジスタを nf 本の並列ゲートに分割。W=10 µm, nf=10 は
  1 µm 幅のゲート 10 本。S/D(ソース/ドレイン)は交互に並び、**偶数列 = 一方、奇数列 = 他方**
- **ゲートコンタクト/パッド**: ゲートポリを金属に引き出す点。活性領域の外側に置く
- **ボディタップ**: 基板(NMOS)/N ウェル(PMOS)を電源に固定する拡散コンタクト。
  無いと DRC(`DF.13/14`)で怒られ、ラッチアップの原因になる
- **MIM 容量**: 金属–絶縁体–金属の容量。GF180 では 2 種類あり、我々の `gf180mcuD` は
  **MIM-B(Metal4 下部プレート / FuseTop 上部電極 / Metal5 端子)**、約 2 fF/µm²
- **via スタック**: Metal2 → Via2 → Metal3 → Via3 → Metal4 → Via4 → Metal5 のように
  層を上がる縦の柱。各段に「パッド」(囲みを満たす小さな金属)が要る

## 3. ツールと責務

| 工程 | ツール | 我々のスクリプト | 備考 |
| --- | --- | --- | --- |
| レイアウト生成 | **gdsfactory**(Python)+ `gf180mcu` PDK プラグイン | `experiments/analog_layout/*.py` | 形状を作るだけ。判定はしない |
| DRC | KLayout + 凍結 PDK デッキ | `run.sh <script> [名前]` | 生成 → DRC → ルール別件数 |
| LVS | Magic(抽出)+ Netgen(比較) | `lvs.sh <gds> <top> <sch.spice>` | 回路図側は `*_sch.spice` |
| PEX | Magic | `pex.sh` | 寄生 R/C 抽出 → ngspice 前後比較 |
| ノイズ | VACASK(+ 上流の GF180 変換器) | `vacask.sh [N]` | シード掃引 → kT/C 比較 |
| 環境 | Docker(IIC-OSIC-TOOLS 2026.07、digest 固定) | `make tools`(初回) | 全部コンテナ内。手元にツール不要 |

### なぜ gdsfactory か
レイアウトが **Python コード**になる。利点は 3 つ:
1. 差分レビュー・Git 管理・CI 再現ができる(手描き GDS は差分が読めない)
2. **パラメトリック**: `sampling_cell_tg(mim_side=15.9)` のように寸法を引数で変え、
   `for` ループで 4 セル → 128 セルに増やせる(Tape-out 2 の要件)
3. 形状の**読み戻し**ができる: 生成したトランジスタの S/D ストラップ位置をプログラムで
   取得し、その座標に配線を置く(`tg_switch.fet_geom`)

欠点: プラグインのプリミティブ(トランジスタ・容量)が **Run 3 の DRC デッキに通らなかった**
(§4.1)。これは我々が修復した。

### ガードレール(方針)
生成器は信用しない。**合否は常に凍結 PDK の DRC/LVS/PEX**で判定する。
プラグイン同梱のモデルやチェッカーは使わない。

## 4. ブロック別の詳細

### 4.1 プリミティブの修復(`fet_fix.py`, `mim_cap.py`)

#### 問題 1: MIM 容量が MIM-A 専用だった
プラグインの `cap_mim` はソースに「MIM-A のみ対応」と明記(Metal2/Metal3/Via2 で描く)。
我々のプロセスは MIM-B なので、via2 の配列 841 個がすべて違反(`V2.3b`)になった。
→ **`mim_cap_b` を設計マニュアル(DRM 10.4.2)から自作**:
- 下部プレート Metal4 が上部電極 FuseTop を **0.6 µm** 囲む(`MIMTM.3`)
- FuseTop 上の Via4 は端から **0.4 µm** 内側、互いに **0.5 µm** 以上離す(`MIMTM.4/9`)
- 下部プレート接続用の Via4 は FuseTop から **0.4 µm** 以上離す(`MIMTM.5`)
- 他の Metal4 から **1.2 µm** 離す(`MIMTM.1`)— via スタックを近づけすぎて一度違反
- `CAP_MK`(117/5)マーカーで囲む。**Magic はこれが無いと容量として認識しない**
  (認識条件: `VIA4 ∧ Metal5 ∧ FuseTop ∧ CAP_MK`)
- 上部電極の面積 25〜10,000 µm²。22.4 µm 角 ≈ 1.0 pF

#### 問題 2: トランジスタのゲートパッドが小さすぎ・近すぎ
プラグインのゲートコンタクト用 Metal1 パッドは 0.34 × 0.23 µm = 0.078 µm²
(`M1.3` の下限 0.1444 未満)、かつ S/D ストラップの角まで斜めに 0.21 µm(`M1.2a` の 0.23 未満)。
パッドを伸ばす余地は、直上 0.11 µm にプラグインの**ボディリング**(COMP)があって無い。
→ **「外科手術」方式**: プラグインセルを平坦化し、
1. リングを削除(`flatten()` はリングを穴あき 1 ポリゴンに合体させるので、
   「コアを包含する形状」も削除対象にする必要があった)
2. ゲートコンタクトを **0.04 µm 外側**に移し、ポリを延長(`CO.3` の 0.07 囲みを維持)
3. パッドを **0.34 × 0.50 µm**(面積 0.17、斜め間隔 0.244)に
4. リングの**左右の脚だけをタップとして再描画**(`DF.13/14` を満たす)、インプラント囲み 0.16 µm

さらに一般化で判明したこと:
- L=0.5 µm ではパッド幅が 0.48(0.34 ではない)→ **サイズでなく位置で**パッドを検出
- L=2 µm(幅広ゲート)では **1 本のゲートに 4 個のコンタクト**が並ぶ → 同じフィンガー・同じ側の
  コンタクトを 1 枚のパッド・1 本のポリ延長にまとめる
- 平坦化後、複数フィンガーのゲートは 1 ポリゴンに合体する → 「上側/下側」の判定に注意

結果: nf=1〜10、L=0.28〜2 µm のすべてで DRC 実違反ゼロ。

> **学び**: 「プラグインが通らない」は行き止まりではなく、PDK のルール本文(`rule_decks/*.rb`)と
> 違反座標(`.lyrdb`)を読めば、原因は必ず特定できる。座標で切り分ける癖が最も効いた。

### 4.2 配線パターン(全ブロック共通)
`route_fet`(`tg_switch.py`)が 1 トランジスタを「配線済みブロック」にする:
- **ゲート**: 上側のパッド群を Metal1 の横バーで結ぶ(下側パッドは削除して配線スペースに)
- **奇数 S/D 列**: ストラップ中央に via1 → Metal2 レール(ネット b)
- **偶数 S/D 列**: ストラップを活性領域の下へ延長 → via1 → Metal2 レール(ネット a)
- **タップ**: 脚から Metal1 を下ろし via1 → Metal2 バー(vss/vdd)
- レールと via パッドは同じ高さ(0.38 µm)にして、はみ出しによる `M2.2a` を防ぐ

物理的直感: ストラップは活性領域の**中**にしか無く、ゲートパッドは**外**にあるので、
上側をゲート、下側を偶数列の引き出しに使い分けると衝突しない。

### 4.3 サンプリングセル(`sampling_cell.py`)
回路図 `transmission_gate.spice`: TG(NMOS W=10 µm nf=10、PMOS W=20 µm nf=10、L=0.28)+ 1 pF。
- NMOS を上、PMOS を下に置き、`in`(偶数列レール)は左の縦 Metal2 で、`hold`(奇数列)は右で結ぶ
- `hold` → 容量上部端子(Metal5)は **Metal2→Metal5 の via スタック**。プレートから 1.5 µm 離す
- 容量下部 → `vss` は **Metal3** で(Metal2 の `hold` 縦線と交差するため層を変える)
- LVS 用に各ネットへ**ピンラベル**(`34/10`, `36/10` 層のテキスト)

ハマった点と教訓:
1. **同層交差ショート**: vss 横バー(M2)が hold 縦線(M2)を横切っていた → M3 に持ち上げ
2. **同一行の via パッド**: hold の M2 給電を容量中心の高さで走らせたら、同じ高さに置いた
   vss スタックの M2 パッドを貫通 → 高さをずらす。**KLayout の接続トレース**で特定
3. Magic は**安定したトップセル名**を要求(gdsfactory の自動名は引数付き)→ ラップして平坦化

結果: DRC 実違反 0、LVS 一致(6 ピン)、41.8 × 23.6 µm。

### 4.4 4 セル配列(`sampling_array.py`)
セルを 26 µm ピッチで 4 段。共通 `in` は各セルの縦 M2 を 1 本のバスで接続、
`vss`/`vdd` は各セルのバーから via2 で **Metal3 の縦バス**へ。
ラベルはセル内では付けず(4 個の同名ラベルが衝突する)、配列レベルで `hold0..3` 等を付与。
LVS 15 ピン一致、41.8 × 101.6 µm(0.0042 mm² — コアの 0.1 %)。

### 4.5 TG スイッチと 4:1 MUX(`tg_switch.py`, `mux4.py`)
回路図 `four_cell_mux.spice`: スイッチは NMOS W=5 nf=5 / PMOS W=10 nf=5、
バスリセット NMOS(L=0.5 µm、W=10 nf=5)。
`tg_switch` は**任意の nf**で動く汎用版(形状読み戻し)。MUX は 4 個を 14 µm ピッチで積み、
右の縦 M2 を `mux_bus`、下にリセット fet。7.4 × 56.4 µm。

### 4.6 ランプ生成器(`ramp_gen.py`)
回路図 `ramp_generator.spice`: PMOS 電流源(W=1、**L=2 µm**)、リセット NMOS(W=10 nf=5 L=0.5)、1 pF。
L=2 µm の幅広ゲートで「複数コンタクト → 1 パッド」の一般化が必要になった。39.2 × 23.6 µm。

### 4.7 コンパレータ(`comparator.py`)— カラムルータ
回路図 `comparator.spice`(9 トランジスタ: 差動対 W=20 nf=10 L=0.5、ミラー負荷 W=40、
テール W=20 L=1、インバータ 2 段)。TG 系と違い、各トランジスタの S/D が別々のネットにつながる。
→ **汎用カラムルータ**:
- 9 個の配線済みブロックを縦に積む
- **ネットごとに Metal3 の縦バス**を右側に 1 本ずつ(10 ネット、ピッチ 0.76 µm)
- 各ブロックのレール(M2)/ゲートバー(M1 → via1 → M2)/タップバーを、その高さで
  横に伸ばして該当バスに via2 で接続
- 高さがブロックごとに異なるので横線同士は衝突しない。M2 横線と M3 縦バスは層が違う

**初回実行で DRC 実違反 0・LVS 一致**。デバイス表を入れ替えるだけで PMOS 入力版も生成
(`cmp_pmos`)。25.5 × 63.7 µm。任意のトランジスタ回路に使える手法。

「Not Manufacturable」と判定した——つまり**密度はハード fail**なので、提出前のフィルは必須。

## 6. PEX と抽出後シミュレーション(サンプリングセル)

手順(`pex.sh`): Magic で `extract do capacitance/coupling/resistance` → `ext2spice cthresh 0 rthresh 0`
→ 寄生 15 C + 15 R 付きネットリスト → 前段と同じテストベンチを ngspice で実行。

| 指標 | 前段 | 抽出後 | 解釈 |
| --- | --- | --- | --- |
| 取得誤差 | 3.20 mV | 3.45 mV | 寄生抵抗で整定がわずかに遅い |
| **クロックフィードスルー** | 5.09 mV | **9.32 mV** | ゲート–hold の結合容量とチャージインジェクションが増えた |
| ホールドドループ(45 ns) | 0.07 µV | 0.20 mV | **要確認**(抽出 MIM モデルの基板ノードの扱いが疑わしい) |

抽出された寄生: `hold` ノード合計 17.5 fF(1 pF の 1.7 %)、`in`↔`hold` 結合 3.4 fF。

**物理的な意味**: TG がオフになる瞬間、ゲート電圧の遷移(3.3 V)が結合容量 C_c を通じて
hold ノードに ΔV ≈ C_c/C_hold × 3.3 V を注入する。C_c が 1 fF 増えるごとに ≈ 3 mV。
対策の定番: (a) ダミースイッチで打ち消す、(b) 相補クロックのタイミング調整、
(c) 配置の対称化、(d) C_hold 増(面積・帯域と引き換え)。
Tape-out 1 の 1 LSB ≈ 52 mV なので 9 mV は 0.2 LSB——致命ではないが、8 bit 化(1 LSB ≈ 13 mV)
では問題になる。**これが「レイアウトが性能に効いた」初めての数字**。

ハマった点: Magic の `extract no all`(LVS 用に寄生を切る設定)を PEX でも使ってしまい
寄生ゼロになった; MIM の寸法パラメータが内部単位で出るので `22.4u` に補正が必要;
MIM モデルは `.lib sm141064.ngspice mimcap_typical` セクションに入っている。

## 7. VACASK によるトランジェントノイズ

### 何が新しいか
ngspice の `.noise` は小信号(周波数領域)解析で、サンプル&ホールドやコンパレータのような
**スイッチング回路の雑音**(サンプリング瞬間に凍結される雑音、しきい値通過時刻のジッタ)は
扱えない。VACASK は過渡解析中にデバイス雑音を注入するので、これらを**直接**シミュレートできる。

### 我々の環境での状況
- コンテナに同梱(`vacask 764f693`、BSIM4 モデルはコンパイル済み)
- GF180 モデルの変換器が古かった → 上流(codeberg)の **Python 変換器 `gf180tovc.py`** を取り込み、
  GF180 PDK 全体を 3 秒で変換。コンテナが aarch64 なので新バイナリは使えず、
  旧バイナリ非対応の構文 2 箇所をパッチ(サリサイドブロック抵抗の線形化、MIM は理想 1 pF)

### 実験(`vacask.sh 40`)
サンプリングセルを、雑音なし 1 回 + 雑音あり **40 シード**で過渡解析(合計 1 秒)。
サンプル後 50 ns の hold 電圧を集計:

| | 値 |
| --- | --- |
| 40 回の広がり(標準偏差) | **61.4 µV rms** |
| kT/C(1 pF、300 K)= √(k_B T / C) | 64.4 µV rms |
| 比 | 0.95 |

**解釈**: スイッチがオンの間、チャネル抵抗 R の熱雑音(4kTR Δf)が RC で帯域制限され、
積分すると R に依存しない kT/C になる。オフになった瞬間の値が「凍結」される——教科書の
kT/C 雑音そのもの。40 サンプルの統計揺らぎ(±11 %)の範囲で一致しており、
**ツールチェーン(VACASK + 変換した GF180 BSIM4 モデル)は信頼できる**と結論できる。

6 bit の 1 LSB ≈ 52 mV に対し 64 µV は無視できる(12 bit・1.5 V フルスケールでも 1 LSB ≈ 366 µV
なので、Tape-out 3 の 12 bit 目標でも 0.18 LSB)。**したがってこの設計で雑音が問題になるのは
サンプリングではなく、コンパレータの遅延ジッタ**——それを VACASK で測るのが次の一手。

## 8. 未解決・注意点

1. **PEX のドループ 0.2 mV / 45 ns** — 4 µA 相当のリークで非現実的。抽出 MIM モデル
   (`cap_mim_2f0_m4m5_noshield` の基板/リーク項)か `vss.tNN` の分割ノードの扱いを確認
2. **密度**はチップレベルでフィル挿入が必須(プラットフォームでハード fail)
3. VACASK: 変換 MIM サブサーキットの寸法パラメータが上書き不可(理想容量で代用中)。
   上流の新しいバイナリを aarch64 でビルドすれば全部解消する可能性が高い
4. ボディタップは各デバイスの左右脚のみ。マクロ統合時にラッチアップ距離(20 µm)を再確認
5. ESD: アナログパッドは HBM ダイオードのみ。ゲート直結ノードには CDM 二次保護
   (ダイオード周長 > 25 µm、直列ポリ抵抗 > 50 Ω)を**設計者が**置く(仕様書に記載済み)
6. **テスト MUX の真理値表が未凍結**(アナログパッド 6 本にモニタ/バイアスを詰める) — 回路図が無いので
   レイアウトも無い。物理側(何を観測したいか)の判断待ち
7. 入力範囲の仕様値(IRSX 相当 0.5–2.0 V を採用するか)が未記載。コンパレータ変種の選択基準になる
