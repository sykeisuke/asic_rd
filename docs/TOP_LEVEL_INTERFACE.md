# Provisional top-level interface

Date: 2026-08-14

This interface freezes logical intent and the 3.3 V library baseline. Pad
order, physical power-domain partition, ESD acceptance, and package pin
numbers remain provider-dependent.

Provider baseline: wafer.space GF180MCU Run 3. The provisional physical target
is the `0.5x1` default pad ring with COB packaging: 56 signal I/Os, including
six documented analog pads, plus 16 power pads. See
[`decisions/0004-wafer-space-run3.md`](decisions/0004-wafer-space-run3.md).

## Digital control and readout

Revised 2026-09-18 for the parallel, bottom-plate architecture (spec 0.6).

| Signal | Direction | Purpose |
| --- | --- | --- |
| `clk` | input | 10-20 MHz nominal conversion/readout clock |
| `rst_n` | input | Active-low global digital reset |
| `start` | input | Start the parallel four-cell conversion |
| `compare_high[3:0]` | analog-to-digital | Comparator state per cell; falling edge captures the Gray count |
| `shift_en` | input | Shift one result bit on rising `clk` |
| `serial_data` | output | LSB-first 32-bit result stream `{cell3, cell2, cell1, cell0}` |
| `data_ready` | output | Result word loaded and available |
| `conversion_busy` | output | Conversion in progress |
| `conversion_done` | output | One-cycle completion pulse |
| `conversion_timeout[3:0]` | output/test | Cell never crossed (its code reads 255) |
| `acquire` | digital-to-analog | 1: cells may track/hold (reference-plate switches enabled by the sampling sequencer) |
| `ramp_connect` | digital-to-analog | 1: all cell input nodes connected to the ramp bus |
| `ramp_reset` | digital-to-analog | Active-high ramp reset (ramp output at 0 V) |

The digital macro exposes 19 scalar signal pins. The per-cell
`SAMPLE[i]`/`HOLD_REF[i]` strobes and their bottom-first ordering are
generated by the analog sampling sequencer from the board-controlled sampling
input; internal analog-control outputs connect to the analog macro rather
than external pads; test multiplexing is still required.

Until 2026-09-18 the interface carried `mux_select[3:0]`, `bus_reset`,
`active_cell[1:0]`, a single `compare_high`, and a 24-bit frame (sequential
MUX architecture, kept as legacy RTL).

## Required analog and test pads

The default half-width ring provides six true analog pads. The logical
interface must therefore be reduced to the following physical-pad budget.

| Priority | Physical pad candidate | Functions |
| --- | --- | --- |
| Must | `analog_in` | Sampling-array input |
| Must | `external_ramp_in` | External-ramp bypass |
| Debug | `analog_mon_0` | Buffered storage node of cell 0 (`VBOT[0]`, the sensed plate) |
| Debug | `analog_mon_1` | Buffered internal ramp bus |
| Debug | `comparator_test_p` | Comparator positive test input |
| Debug | `analog_test_mux` | `VREF` override / comparator reference test input or selected bias control/monitor |

`comparator_out_mon` is a digital output. `sample_clock_in` is a digital input.
Comparator and ramp bias functions shall share `analog_test_mux` or use
internally generated settings unless provider review makes more analog pads
available. The test-MUX truth table must be frozen before pad-ring integration.

## Power domains

Nominal `AVDD`, digital-core supply, and I/O supply are frozen at 3.3 V. The
official `0p5x1` template has one core `VDD/VSS` pair and seven I/O
`DVDD/DVSS` pairs and does not provide separate analog-core and digital-core
rails without modification.

Revised 2026-08-30: all grounds are tied together on the provider's default
COB breakout, so a separately measurable analog ground is not achievable in
this package. The separate-current requirement is reduced to **`AVDD` only**;
`AVSS`, `DVSS_CORE`, and `IOVSS` share the common ground. The `bidir[43:42]`
positions of the `0p5x1` ring are re-typed into a second core `vdd/vss` pair
(`gf180mcu_ocd_io__vdd`/`__vss`) carrying `AVDD`; this ring passed the
provider platform's CoB precheck on 2026-08-31 (wafer.space issues no written
confirmations, so the automated check is the authority). The supply topology
is therefore frozen; domain crossings, clamps, and ESD ownership between the
`AVDD` and digital-core domains are now design work for the top-level
integration. See [`PDK_PAD_SUPPLY_FREEZE.md`](PDK_PAD_SUPPLY_FREEZE.md).
